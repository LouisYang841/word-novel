# Word Novel 📚

上传喜欢的英文小说，AI 自动提取重点词，生成英文填空 / 选择题来背单词。

- **纯静态**：无后端、无构建，全部逻辑在浏览器里跑
- **数据本地**：书籍、练习、进度、生词本全部存在浏览器 localStorage
- **BYOK**：自带 API Key，支持 OpenAI 兼容接口（OpenAI / DeepSeek / OpenRouter / 腾讯 TokenHub 等）和 Google Gemini，Key 只存本地
- **生词本 + 复习**：做错的词自动进生词本，Leitner 间隔复习
- **可导出**：全部数据可导出 JSON 备份，生词本可导出 CSV

## 使用

1. 打开网站 → 「设置」配置 AI 服务商和 API Key → 测试连接
2. 「书架」上传英文小说 .txt
3. 「练习」直接开始——题不够时会**自动逐块生成**（做一块生一块，可中断）；也可以在书详情页提前批量生成
4. 错词自动进生词本
5. 生词到期后，练习页顶部会出现复习提醒

## 本地开发

ES modules 需要 http 服务（直接开 file:// 不行）：

```bash
cd word-novel
python -m http.server 8080
# 浏览器打开 http://localhost:8080
```

## 部署

推送 main 分支后 GitHub Pages 自动重新部署：

```bash
git add -A && git commit -m "..." && git push
```

# Vibe Coding 实录：这个项目是怎么做出来的

本项目全程由一次 Vibe Coding 会话完成：**人只负责出点子、做裁决、报 bug；AI（CodeBuddy Code）负责计划、写码、排查、部署**。没有一行代码是人手写的，13 个 commit 对应 13 轮对话。

> 📱 **全程在一台 OnePlus 15 安卓手机上完成**：Termux 环境 + CodeBuddy CLI，底层模型为 GLM-5.3-Flash。建仓、写码、调试、部署 GitHub Pages，**全程未使用电脑**。

以下是完整流程复盘，供想复刻这种协作方式的人参考。

## 第 0 步：一句话点子 → 计划先行

> **人**：「我想做一个背单词的网站，大概就是可以自己上传喜欢的小说然后 AI 自动提取重点词改成英文填空这样，然后用静态页面，用户数据 localStorage，AI 功能采用 BYOK。用本机的 gh 开一个 GitHub Pages 来部署。」

> **AI**：没有直接动手，而是先进入**计划模式**，把 4 个关键分歧点摆出来让人选：
> - BYOK 格式 → 选了「多协议」（OpenAI 兼容 + Gemini 兼容）
> - 技术栈 → 选了「纯 HTML/JS/CSS，无构建」（Termux 手机环境，越简单越好）
> - 玩法 → 选了「填空 + 选择两种都要」
> - 仓库 → 新建公开仓库（Pages 免费版要求公开）
>
> 然后产出一份含文件结构、数据模型、AI prompt schema、部署命令的完整计划，**人批准后才开工**。

## 第 1 步：一轮对话从 0 到上线

> **AI**：按计划一次写完 14 个文件（约 1700 行），跑语法检查 + HTML/JS 元素 ID 一致性检查，`gh repo create --push` + API 开启 Pages，验证站点 HTTP 200。
>
> **产出**：`059ae9b` Initial word-novel

**经验 1：绿地项目 + 明确计划，0 → 上线只需一轮。** 计划阶段花的功夫（数据模型、prompt schema）在后面所有迭代里都在还债——利息是正的。

## 经验总结

1. **分工清晰**：人提供「产品判断」（要不要这个功能、交互对不对劲、真机上什么表现），AI 提供「实现能力」（写码、排查、部署）。人从不需要看代码，但每一步都知道 AI 在做什么。
2. **真机反馈是最好的测试**：手机浏览器没有开发者工具，第 6 轮加的日志页成了之后所有 bug 的定位抓手——第 8、9 轮都是靠日志（或日志的缺失）破案的。
3. **「没反应」类 bug 三板斧**：先查代码（第 12 轮真是没绑定）、再查缓存（第 8 轮新旧混用）、最后加可观测性让人自己能验证（版本号打点）。
4. **部署迭代的最大敌人是缓存**，不是代码。network-first SW 一次投入，之后 13 轮迭代再也没有出现过「改了没生效」。
5. **低级错误是常态**：查错字段（第 9 轮）、忘绑事件（第 12 轮）都发生在 AI 身上——完整保留 AI 原始返回的日志让这类问题一轮就能钉死，而不是反复猜。
6. **用户的「不对劲」值得直接重做**：第 13 轮人一句「逻辑不太对劲」，AI 没有辩解，按人描述的交互重做——产品感觉在人手里，实现手感在 AI 手里。

> 技术栈复刻清单：纯静态 HTML/ES Modules、localStorage（`wn:` 前缀命名空间）、BYOK 多协议（OpenAI 兼容 + Gemini 兼容，浏览器直连）、network-first service worker、GitHub Pages + gh CLI。零依赖、零构建。
>
> 📱 复刻环境清单：一台安卓手机 + [Termux](https://termux.dev)（提供 node / git / gh / python 等工具链）+ CodeBuddy CLI（`npm i -g @tencent-ai/codebuddy-code`，底层 GLM-5.3-Flash）。装好这三样，你的口袋就是完整的开发机。
